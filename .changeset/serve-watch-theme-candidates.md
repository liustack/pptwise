`pptwise serve` now follows the bound theme wherever its name resolves, not only the file the first build happened to find. Inside the project root, every place the name could resolve to is watched, so a workspace `themes/<name>.theme.json` created later shadows the preset the moment it lands, its edits and removal follow, and a spec rebound to another name moves the watch to that name's files before they exist. Every 2 seconds the name is also resolved again the way a build resolves it, and the answer, a digest of the theme file's content, the built-in's id, or the lookup's error, is compared with the theme the last build reported it was drawn with. A different answer triggers a rebuild. That covers a `themes/` created, deleted, moved away, or replaced by a plain file anywhere on the lookup chain, including above the project root where no watcher can sit, a theme file rewritten with its size and timestamp kept, and a lookup that starts failing or stops failing. A plain file named `themes` above the project no longer stops `serve` from starting when a nearer theme file answers the lookup, a check still running when the server closes or a build finishes discards its result instead of scheduling a rebuild, and a `serve` that fails while attaching its watchers closes the ones it had opened before it reports the error.
