`pptwise serve` now follows the bound theme wherever its name resolves, not only the file the first build happened to find. Inside the project root, every place the name could resolve to is watched, so a workspace `themes/<name>.theme.json` created later shadows the preset the moment it lands, its edits and removal follow, and a spec rebound to another name moves the watch to that name's files before they exist. Every 2 seconds the name is also resolved again the way a build resolves it, and a different answer (another file, a changed file, a built-in again, an error) triggers a rebuild. That covers a `themes/` created, deleted, moved away, or replaced by a plain file anywhere on the lookup chain, including above the project root where no watcher can sit. A plain file named `themes` above the project no longer stops `serve` from starting, and a check still running when the server closes or a build finishes discards its result instead of scheduling a rebuild.
