`pptwise serve` now follows the bound theme wherever its name resolves, not only the file the first build happened to find. Inside the project root, every place the name could resolve to is watched, so a workspace `themes/<name>.theme.json` created later shadows the preset the moment it lands, its edits and removal follow, and a spec rebound to another name moves the watch to that name's files before they exist. Every build now reads all of its theme inputs once, at its start (the bound name, where it resolves to and that file's content, and the deck's own `theme.json` the rebind guard compares against), and reports that record whether it succeeds or fails. Every 2 seconds the same record is collected again and compared with the last build's. A different record triggers a rebuild; an identical one, a persistent error included, does not. That covers a `themes/` created, deleted, moved away, or replaced by a plain file anywhere on the lookup chain, including above the project root where no watcher can sit, a theme file rewritten with its size and timestamp kept, a lookup that starts failing or stops failing, a theme read that was broken only for the length of one save (in a deck project as well as for a bare IR), and a rebind refusal lifted by a change to the deck's `theme.json` through a symlink. A plain file named `themes` above the project no longer stops `serve` from starting when a nearer theme file answers the lookup, a check still running when the server closes or a build finishes discards its result instead of scheduling a rebuild, a `serve` that fails while attaching its watchers closes the ones it had opened before it reports the error, and a file event the watcher cannot act on (a directory swapped for a plain file as the event arrives) is reported as a failed build and retried instead of ending the process.
