Nine themes are renamed, and four keep their id but lose a label that named a customer. A theme name says how a deck speaks, never who it is for, so `consulting` is now `brief` (Brief), `academic` is `thesis` (Thesis), `insight` is `ledger` (Ledger), `tech` is `terminal` (Terminal), `enterprise` is `bulletin` (Bulletin), `classroom` is `homeroom` (Homeroom), `campaign` is `rally` (Rally), `pulse` is `clinic` (Clinic), and `terra` is `almanac` (Almanac). `crayon`, `arena`, `ember` and `runway` keep their ids and are now labelled Crayon, Arena, Ember and Runway instead of Kids Education, Esports & Entertainment, Startup Pitch and Fashion Runway. The five motifs that carried a renamed theme's word travel with it, so a copied theme file now reads `rally-motif`, `homeroom-motif`, `bulletin-motif`, `clinic-motif` and `almanac-motif`. The industry words move to where they belong: the occasions table still says business, education, finance, tech, health and sustainability, and every theme's positioning and audience still name the rooms it suits.

A theme id is a public interface, so nothing is aliased and nothing is handed back. Naming a retired id fails wherever a theme is resolved (IR validation, spec validation, CLI lookup, built-in and preset lookup) and wherever one is created (the theme-file contract, `registerTheme`, install, preset copy, colour fork, `theme new --id`, `theme fork --id`), and every one of those errors says the name the theme became, so a deck moves over in one edit. Lookup refuses the old name before it searches, so a workspace file that kept it cannot answer to it either. No page changes: every rendered page in the review gallery is byte-identical to what its old id drew.
